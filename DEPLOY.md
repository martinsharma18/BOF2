# Deploying BOF2 (free)

```
 phone / browser
       │
       ▼
  Vercel  (frontend, fast CDN)  ── /api/* ──►  Render  (API, Docker, Singapore)
                                                  │            │
                                                  ▼            ▼
                                            Neon Postgres   Cloudinary
                                            (database)      (photos)
```

The browser only ever talks to the Vercel address; Vercel forwards `/api/*` to Render. So there is
no CORS setup, and "install app" and push notifications work on one domain.

Do the steps **in this order**. Steps 1–3 only need doing once.

---

## 1. Database — Neon (free, no expiry)

1. Sign up at **neon.tech** (GitHub login is fine).
2. **Create project** → name `bof2`, Postgres 17, region **AWS Asia Pacific (Singapore)**.
3. Open **Connect**. Turn **Connection pooling OFF** (the API runs migrations on start and needs a direct connection).
4. Copy the connection string. It looks like
   `postgresql://neondb_owner:xxxx@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   Keep it for step 4. You don't create any tables: the API creates them on first start.

## 2. Photos — Cloudinary (free, 25 GB)

Render's free disk is wiped on every deploy, so photos must live elsewhere.

1. Sign up at **cloudinary.com**.
2. Dashboard → **API Keys** → copy the **API environment variable**:
   `cloudinary://123456789012345:abcdEFGH...@your-cloud-name`
   (copy only the part starting with `cloudinary://`). Keep it for step 4.

## 3. Push-notification keys (once, keep forever)

On your PC, in any folder:

```bash
npx web-push generate-vapid-keys
```

It prints a **Public Key** and a **Private Key**. Save both somewhere safe (password manager).
Changing them later turns phone notifications off for everyone until they turn them on again.

## 4. Backend — Render

1. Push the code to GitHub (`main` branch).
2. Render → **New** → **Blueprint** → choose the `BOF2` repo. Render reads `render.yaml` and
   shows one web service, `bof2-api` (free, Singapore, Docker).
3. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `ConnectionStrings__Default` | Neon link from step 1 |
   | `Seed__AdminEmail` | super admin login email, e.g. `admin@yourdomain.com` |
   | `Seed__AdminPassword` | a strong password (8+ characters, at least one digit and one lowercase letter) |
   | `Cloudinary__Url` | `cloudinary://...` from step 2 |
   | `WebPush__PublicKey` | Public Key from step 3 |
   | `WebPush__PrivateKey` | Private Key from step 3 |
   | `WebPush__Subject` | `mailto:` + your email, e.g. `mailto:you@gmail.com` |

   `Jwt__Key` is generated by Render automatically.
4. **Apply**. The first build takes ~5–8 minutes. When it is live, open
   `https://<your-service>.onrender.com/health`. It should say `Healthy`.
5. Note the exact address Render gave the service (top of the service page). If it is **not**
   `https://bof2-api.onrender.com`, change both addresses in `frontend/vercel.json` to yours and push.

> Free plan: the API sleeps after 15 minutes without visitors, and the first request after that takes
> ~30–50 s. Keep it awake for free: **uptimerobot.com** → New monitor → HTTP(s) →
> `https://<your-service>.onrender.com/health` → every 5 minutes. (One always-on service fits in
> Render's 750 free hours a month.)

## 5. Frontend — Vercel

1. Vercel → **Add New… → Project** → import the `BOF2` repo.
2. **Root Directory: `frontend`** (click Edit). Vercel detects Vite. Leave build command `npm run build`
   and output `dist` (they also come from `frontend/vercel.json`).
3. No environment variables are needed. **Deploy**.
4. Open the Vercel address on your phone, sign in with the super admin from step 4, and try:
   register, post with a photo, apply, chat, **Settings → Phone notifications → Turn on**.

## Updating later

Push to `main`: Render and Vercel both redeploy on their own. Database changes (EF migrations) are
applied automatically when the new API starts.

## When something is wrong

| Symptom | Look at |
|---|---|
| Site loads but login says "Cannot reach the server" | Render service **Logs**; the API may still be waking up or failed to start. Check that `vercel.json` has your Render address |
| Render log: `password authentication failed` / `SSL` | `ConnectionStrings__Default`: copy it from Neon again (pooling OFF) |
| Render log: `Jwt:Key must be configured` | `Jwt__Key` missing: Environment → add it with **Generate** |
| Photos upload but disappear after a deploy | `Cloudinary__Url` is empty or wrong |
| "Phone notifications are not set up on the server yet" | `WebPush__PublicKey` / `WebPush__PrivateKey` missing |
| Can't sign in as admin | `Seed__AdminEmail`/`Seed__AdminPassword` are only used the **first** time; the account isn't changed later |
